1 · Echo processing

What "FT each echo" does. Each echo is Fourier transformed along its points. In a constant magnetic-field gradient, frequency maps to position, so the decay can be analysed at every depth z instead of as one number. The analyses you choose below are then repeated at each position.

The window defaults to −200 to +200 µm (+ z = + frequency = closer to the magnet). Clear both ends to use the region where the profile exceeds 10% of its maximum. Exponential fits are done every Exp-fit spacing µm (blank = the natural resolution 1/(points × dwell × γG); zero-filling interpolates but adds no resolution). The ILT is cheap, so by default it runs at every zero-filled point to match the heat maps. Positions whose signal is below Min signal are not fitted (they would only fit noise) and show as gaps. The window-summed decay is also fitted, as a reference.

What this does. The data are echo trains measured at several diffusion-encoding delays. The 2D inverse Laplace transform finds the distribution of T2 and diffusion coefficient D that reproduces them, without assuming how many components there are:

Units. You enter and read D in m²/s. Internally the solver works on D × 10⁹ (and b-values × 10⁻⁹) to keep the numbers near 1, and converts every result back.

The b-values are calculated here, not read from the spectrometer. For the stimulated echo in a static gradient, b = (γG)² τ² (Δ + 2τ/3), with γ = 2π × 42.577 MHz/T (¹H), τ the encoding delay, Δ the storage time (Kea: acqu.par tauMin, tauMax and nrPntsTau, log-spaced, and DELTA; Tecmag: the sequence's delay table plus the pulse width, and its DELTA) and G the gradient you enter above (default 23.67 T/m for the Kea magnet, 6.59 T/m for the Tecmag magnet; it is not in the files). The echo time sets the echo axis of the decay, not b. The spectrometer's own axis files are only used as a cross-check: they should have the same τ and Δ dependence, and the gradient they correspond to is shown next to the range below. Changing G rescales every b (and so every D).

What the data can resolve. A diffusion coefficient is only measurable if the signal decays over the b-values you used: roughly from 1/bmax to 5/bmin (shown above for this dataset). Outside that range the regularised solution is extrapolation, not measurement, and it can carry a lot of "signal" (the penalty does not discourage large amplitudes where the kernel is ~0). The results flag regions outside it, and "Use the range the b-values can resolve" restricts the grid to it.

Cost. The solve is one dense problem of (T2 points × D points) unknowns. 50 × 25 takes seconds; 100 × 25 about a minute natively and several times longer in the browser (about 1 GB of memory). You get a time estimate, based on a short timed trial on this computer, and a confirmation before long runs, and you can stop a run (this restarts Python, keeping your data and settings).

Larger α = less smoothing. The method is ill-conditioned (exponentials in b overlap): positions and shares are reliable to within a factor, not exactly, and shares can shift with α. Regions are connected areas above the threshold (overlapping peaks can appear as one).

Show more

Why a model as well as the map. The map above is a regularised distribution: it shows where signal is, but it gives no error bars, and it can put weight where the data say nothing. The few-population model fits a small number of discrete populations,

S(t, b) = Σk Ak exp(−t / T2,k) exp(−b Dk), Ak ≥ 0 (no offset),

each with an amplitude, T2 and D and a confidence interval. It is fitted for 1 to 4 populations, starting from the regions the map found, and the number the BIC prefers is used unless you choose one. MCMC and the bootstrap (Advanced settings, below) sample this model.

Limits. Each population is a single exponential in T2 and in b (free diffusion). Restricted diffusion or non-exponential relaxation can show up as extra populations. A population slower than the b-values can resolve is reported as a bound (no interval); one faster than that leaves no signal in the data, so it is never found, and the map's weight there is extrapolation.

Fits the decay with a sum of exponentials; each component has an amplitude A and a relaxation time T2. The constant offset c absorbs a flat baseline. Components are listed from fastest to slowest relaxing.

Compare 1–4 components also fits one to four components and ranks them by ΔBIC, which rewards a good fit but penalises extra parameters (more components are not always justified by the data). Intervals come from the least-squares covariance at the confidence level in Advanced settings (below).

Advanced
Show more

The inverse Laplace transform finds the distribution of T2 values that reproduces the decay, without assuming how many components there are. The solution is regularised (smoothed) so it is stable against noise.

Larger α = less smoothing (noisier spectrum); the typical range is log₁₀ α = 6 to 10 (the arrows step by one decade). The grid never has more points than echoes. Peaks below the threshold are ignored in the peak table. Peak areas (the sum over a peak) are the signal amounts, which is how they compare with the exponential components.

MCMC (Bayesian posterior of the multi-exponential fit)(Bayesian posterior of the few-population model)
Show more

What MCMC does. A least-squares fit gives one best answer and a symmetric error bar. MCMC (Markov chain Monte Carlo) instead explores every set of parameter values that is consistent with your data and its noise, and records how plausible each one is. The spread of the visited values is the uncertainty, and unlike an error bar it can be lopsided or show that two parameters trade off against each other. It matters most when the answer is poorly determined: a window shorter than T2, or components with similar T2.

How it is done here. An ensemble of "walkers" moves through parameter space (the emcee sampler; Foreman-Mackey et al. 2013). The first burn-in steps are discarded while the walkers settle. Priors: amplitudes flat and ≥ 0; T2 log-uniform between a tenth of the first and ten times the last echo time, ordered fast → slow so components cannot swap; offset flat; σ log-uniform if sampled. It uses the model chosen on the Process tab. For T₂–D, each population has an amplitude, a T2 and a D (log-uniform inside the range chosen on the Process tab, by default what the b-values can resolve); there is no offset.

Reading the results. The trace plot should look like stationary noise; the corner plot shows each parameter's distribution and the correlations between pairs; the autocorrelation time says how many steps give one independent sample. The page warns when the chain is shorter than ~50 autocorrelation times. The default 6000 steps is about 100 for a typical decay; strongly correlated parameters need more. Intervals are central credible intervals at the level above.

Bootstrap (refit surrogate decays)(refit surrogate data sets with the few-population model)
Show more

What the bootstrap does. The bootstrap asks "if I repeated the measurement, how much would the answer move?" by doing exactly that on the computer: it builds many surrogate decays (the fitted curve plus noise like yours), refits each one, and reports the spread of the results. Unlike MCMC it needs no probability model of the parameters, and it works for the ILT spectrum too, where it gives an uncertainty band and intervals on each peak's T2 and share of the signal.

Where the noise comes from. The preferred source resamples the values actually measured in the imaginary channel (which contains only noise after phasing), so no Gaussian assumption is needed. The alternatives are to resample the fit's own residuals (which inherits any model misfit) or to draw Gaussian noise with the measured σ. Real-valued data falls back to residual resampling.

Intervals are percentile intervals at the confidence level above. More replicates smooth the intervals but take longer; a few hundred is usual.

MCMC and the bootstrap run after the processing, once you have confirmed a time estimate; their results appear on the Results tab.

What does “Export params + script” give me?

Two files that repeat this analysis on your own computer, with the settings you have chosen here: params.toml (every setting) and process_nmr.py (a small script). The script can run one dataset or a whole folder of them as a time series, and it writes the same tables and figures as this page. Nothing is uploaded.

To run it: install Python 3 and the package once (pip install git+https://github.com/tkmeldrum/nmr-dashboard), put both files in one folder, then in a terminal:

python process_nmr.py DATA_FOLDER            # one dataset
python process_nmr.py DATA_ROOT --batch      # every dataset under a folder

Results go into a processed_… folder inside each data folder. Run python process_nmr.py --help for the other options.

    Show the model and how to read the spectrum

    Orange diamonds are the exponential components. Each is drawn at the height an ILT peak holding the same amount of signal would have (using the width of the nearest ILT peak), so when the two analyses agree a diamond sits on top of its peak; labels give the fractions.     How to read the α sweep

    Each point is the ILT of your decay run again with a different smoothing strength α (labelled, from the sweep range you set). The horizontal axis is how badly that spectrum fits the data (RMSE, lower is better); the vertical axis is how rough the spectrum is (its curvature relative to its size, lower is smoother). Both axes are logarithmic.

    Small α fits the data closely but gives a jagged spectrum with spurious peaks (top left); large α gives a smooth spectrum that no longer fits the data (bottom right). The curve is therefore L-shaped, and a good α sits near the bend, where more smoothing starts to cost fit quickly. A sensible choice also has an RMSE close to the noise level in the table above: fitting below the noise means fitting noise.

    Not every dataset gives a clean L. If the RMSE hardly changes across the sweep, or the path doubles back on itself, the data are too noisy (or too simple, such as a single exponential) for the curve to pick α. Then judge by the spectra instead: choose an α where the peaks you care about stay put when α changes by a factor of ten either way.

    Compare with the α you used (in the summary line below the spectrum). If it sits far along either arm of the L, try a value nearer the bend and check that the peaks you care about do not move much; peaks that appear or vanish as α changes are not well determined.
